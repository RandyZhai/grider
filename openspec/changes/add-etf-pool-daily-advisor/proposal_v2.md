## Change: ETF 池每日自动分析、多算法建议与持仓感知

### Why
用户需要持续跟踪一组国内 ETF 的网格交易机会。现有能力只能逐个分析，且将“ATR 网格 + 低频/均衡/高频”视为唯一方案，不能比较等差、等比、ATR、布林带等不同网格算法，也不了解当前现金、持仓成本、仓位及活动网格状态。因此建议可能在空仓回测中成立，但对真实持仓不可执行。

同时，后续历史模拟与向前模拟交易也需要复用每日分析中的数据准备、指标计算、算法调用、统一回测、评分、解释与账户约束能力。每日运行不能实现为封闭脚本，而应建设为可被定时任务、手工分析、历史回放和 Paper Trading 调用的模块化分析流水线。

### What Changes
- 新增 ETF 池管理及 SQLite 持久化。
- 新增“策略中心”：前台创建策略模板，选择基础网格算法、过滤器、资金管理及参数。
- 首批基础算法：固定等差、固定等比、ATR 自适应、布林带自适应。
- 首批可组合过滤器：ADX 趋势过滤、均线方向过滤、波动率异常过滤和区间突破保护。
- ETF 可绑定一个主策略及多个候选/基准策略，支持固定、比较、自动推荐三种运行模式。
- 每日分析拆分为可复用流水线：数据准备 -> 特征计算 -> 候选选择 -> 统一回测/模拟 -> 评分 -> 持仓约束 -> 行动建议 -> 报告。
- 新增账户、人工持仓及活动网格状态，使每日建议区分“市场层推荐”和“账户层可执行建议”。
- 新增统一模拟执行内核的接口与数据模型，供历史回放及未来 Paper Trading 复用；本变更先实现持仓感知和历史模拟接口，不自动下单。
- 新增日线 SQLite 本地化及 5 分钟数据按标的/交易日持久缓存，解决 Docker/免费源不稳定时的回测闭环。
- 新增独立 scheduler 服务，规避 Gunicorn 多 worker 重复执行，并使用原子领取、heartbeat、lease、attempt 和失败重试。
- 新增报告 API 与前端 ETF 池、策略中心、持仓和每日建议页面。

### Goals
- 多算法、可配置、可扩展、结果可复现。
- 每日分析能力可由 API、scheduler、历史模拟和 Paper Trading 共同调用。
- 同一数据窗口、资金、手续费、滑点和成交规则下公平比较策略。
- 结合当前持仓和资金约束，输出可执行行动建议。
- 外部数据源失败时，尽量使用本地日线和分钟缓存降级运行。

### Non-Goals
- 券商实盘下单或账户同步。
- 自动采用推荐策略或自动修改真实持仓。
- 多用户及权限体系。
- 全市场扫描，仅分析池内标的。
- 第一阶段不承诺盘中实时 Paper Trading；仅预留执行接口并支持历史分钟回放。

### Impact
- 新增能力域：strategy、analysis_pipeline、portfolio、simulation、market_data、pool、reports。
- 既有算法通过 adapter 接入统一算法接口，避免直接修改成熟算法内部。
- 现有 BacktestService 逐步改为调用统一 SimulationEngine，确保回测和未来模拟交易使用同一成交语义。
- 数据库新增算法目录、策略模板、绑定、运行、评估、持仓、策略实例及数据质量字段。
- Docker Compose 建议拆分 web 与 scheduler 两个服务，共用同一镜像和持久化卷。
